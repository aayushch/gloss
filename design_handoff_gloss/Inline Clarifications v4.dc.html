4Warm paper, finalized — with conversation navigation

Name: Gloss. A gloss is a short explanation written beside a word in a text — exactly what an inline clarification is. One syllable, reads as a verb (“gloss that line”), and the product sits literally in the margins of a conversation. Alternates considered: Margin, Aside, Footnote, Marginalia.

Agents. Gloss has no account — it is a local shell over CLI agents (Claude Code, Codex CLI, Gemini CLI). The rail footer shows the app and the active agent; the gear opens Settings with agent selection (installed/not-found state, command name) and appearance. The chat header echoes the agent command so you always know who is answering.

Warm paper carried forward from 3a/3b; cool graphite dropped. A left rail lists conversations grouped by recency; the active one expands to show its inline clarifications, so a clarification is reachable from the nav like any other turn — click one to jump to it. Switching conversations keeps each one's clarifications. Both panels toggle light/dark.

Spec — rich responses. Model markdown renders as-is: headings, bullets, nested numbered lists, bold, italic, inline code, fenced code blocks. Code blocks must be syntax-highlighted — a language label plus per-token colouring (keywords, types, function names, numbers, strings, comments) from a dedicated token palette that has a light and a dark variant tuned to the theme; the sample uses a lightweight tokenizer, production should use a real highlighter (e.g. Shiki/Prism) with the same colour roles. Selection-to-ask works across all of it — inside headings, inline code, and code blocks — and the mark keeps the original formatting; a code block gets a “clarified below” marker instead of an in-text mark.

Spec — clarifications are recursive. A clarification reply is a full model turn, so everything the main response supports applies inside it: markdown (headings, lists, bold/italic, inline code), fenced code blocks with syntax highlighting from the same token palette, and the same highlight-to-ask affordance — selecting text inside a clarification reply opens a nested clarification beneath it, with its own collapsible header, follow-ups, and rail entry. The only differences are presentational (smaller type, recessed well, indent per nesting level); behaviour is identical at every depth. The mock demonstrates two levels (Clarification 01 → 03); deeper levels follow the same pattern.
